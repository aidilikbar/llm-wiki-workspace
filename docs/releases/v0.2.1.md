# v0.2.1 (2026-10-30)

A fix for macOS.

## Fixed

- On macOS, a successful install printed a false line before the real result:

  ```
  Installation failed: unexpected error on line 586 of install.sh, while running: git -C "$TARGET" rev-parse --show-toplevel 2> /dev/null
  ```

  The installation was complete. The line came from a check that is expected to fail
  for a new folder ("is this folder already inside a git repository?"). macOS ships bash
  3.2, which runs the installer's error handler inside that check even though the
  installer handles the failure. Newer bash versions do not, which is why the tests on
  Linux passed.

  If you installed with v0.2.0 on a Mac and the report ended in "Installation
  complete.", your workspace is fine. Nothing needs redoing.

## Changed

- The tests now require exactly one result line per run, so a stray "Installation
  failed" next to "Installation complete" fails them.
- CI on macOS runs the whole test suite a second time under `/bin/bash` 3.2.
- The release workflow runs the same checks on Linux and macOS and publishes nothing
  unless both pass. v0.2.0 was published while the macOS check was failing.

## Known issues

Unchanged from v0.2.0: the npx package is not on npm yet, the Node installer cannot ask
questions on Windows, and two workflow documents are still stubs.
