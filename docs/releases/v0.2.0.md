# v0.2.0 (2026-10-30)

The installer now checks its own work and hands over to your agent. There are no manual
steps after it finishes.

```bash
curl -fsSL https://raw.githubusercontent.com/aidilikbar/llm-wiki-workspace/main/install.sh | bash
```

## Changed

- **Every run ends in one verdict**, for a workspace and for a `.handoff/` setup alike:
  `Installation complete.`, `Installation failed: <reason>`, or `Installation finished,
  with problems.` The exit code matches: 0 for complete, 1 otherwise.
- **A folder that already has files in it is refused**, before any other question is
  asked. Use `--merge` to add only the missing files (the old behaviour) or `--force` to
  overwrite.
- **`--handoff` refuses a workspace folder.** The exchange belongs in the code repo the
  executor works in. `--force` overrides.

## Added

- **Project questions:** the project name, what you are making, and your name.
- **`instruction.md`:** a kick-off brief written from those answers. Tell your agent
  "Read instruction.md and start the kick-off" and it drafts the vision, constraints,
  requirements and first backlog for your approval.
- **Owner fields filled in:** your name replaces `owner: TODO` in every installed file.
- **A verified hook:** with git, the installer proves in a throwaway repository that a
  file without front matter is rejected and a valid one accepted, then makes the first
  commit.
- **Flags:** `--project`, `--about`, `--owner` and `--merge`.
- **Version pinning:** `LWW_REF=<tag>` installs a specific release.

## Fixed

- The pre-commit hook checked the file on disk, not the staged version. A file staged
  without front matter got committed if only the disk copy was fixed.
- The README's manual hook check left its test file staged, and the next commit picked
  it up. The check is now done by the installer.
- A folder you cannot write to gives `cannot write to <folder> (permission denied)`
  instead of an internal error.

## Upgrading

- Scripts that re-ran the installer into an existing workspace now need `--merge`.
- To add `instruction.md` to a workspace made with v0.1.0, run the installer in it with
  `--merge --project "<name>" --about "<what it is>"`. Existing files are kept, so their
  `owner: TODO` fields stay as they are.

## Known issues

- `npx llm-wiki-workspace` is not on npm yet. Use the curl route.
- On Windows the Node installer cannot ask questions; pass flags.
- `system/workflows/documentation-workflow.md` and `onboarding.md` are still stubs.

## Rollback

The v0.1.0 installer cannot be pinned through curl, because it downloads from `main`.
To install v0.1.0, clone the tag and run its own installer:

```bash
git clone --depth 1 --branch v0.1.0 https://github.com/aidilikbar/llm-wiki-workspace lww-0.1.0
bash lww-0.1.0/install.sh
```
