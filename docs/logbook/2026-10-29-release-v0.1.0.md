**Worked on:** Preparing the first tagged release.

**Outcome:** shipped

**What happened:**
The version was set to 0.1.0 in all three places it lives — `package.json`, `install.sh`
and `bin/cli.js` — replacing the 1.1.0 that the previous entry planned to tag; the owner
chose 0.1.0 for the first release. The release workflow now
refuses to publish if the tag disagrees with any of the three version strings, and takes
its notes from `docs/releases/<tag>.md` rather than generating them from commit titles.
Before tagging, the previous commit was rewritten to remove AI attribution trailers from
its message; file contents were unchanged.

**What surprised us:**
The version number lived in three files with nothing checking they agreed. Any one of
them could have shipped wrong and every test would still pass, because each test asked
one installer for its own version. Now the release itself checks.

The README advertised `npx llm-wiki-workspace` while the package had never been published.
A documented route that 404s is worse than an undocumented one. It now says so until it
is published.
